# Patterns

Patterns define composition. ACANTO SELVA에서는 generic components보다 page rhythm을 지키는 데 중요합니다.

## 1. Editorial Hero

- logo/navigation보다 object 또는 image hierarchy가 먼저 느껴짐
- copy 1–3개 요소
- wide whitespace
- optional asymmetric alignment
- CTA는 실제 다음 행동이 있을 때만

Avoid: centered headline + button + gradient의 generic hero.

## 2. Object Isolation

하나의 제품을 넓은 field 안에 고립시켜 silhouette와 material을 보여준다.

- product uses contain
- background remains quiet
- metadata는 멀리 떨어진 작은 block으로 둘 수 있음
- negative space는 viewport마다 재조정

## 3. Asymmetric Image / Text Pair

12-column grid 위에서 image와 text의 시작/끝을 다르게 둔다.

- desktop: 7/5, 8/4, 5/7 등
- mobile: 순서와 의미에 따라 stack
- 매 section 같은 분할을 반복하지 않음

## 4. Archive Index

오브젝트나 symbol을 목록/색인처럼 보여준다.

- image, name, year/series, short meta
- hover/focus에서 detail reveal 가능
- 정보 구조는 명확하게 유지

## 5. Narrative Sequence

Research → Symbol → Form → Detail → Product처럼 점진적으로 설명한다.

- image scale contrast
- narrow text와 full image 교차
- viewport마다 2–3개 핵심 정보
- scroll effect는 narrative 이해를 돕는 경우만

## 6. Teaser Sequence

```text
ENTRY → OBJECTS → ORIGIN → SYMBOL → STANDARD → ARRIVAL
```

First object: GUARDIAN.  
Symbols: Eye, Knot, Labyrinth, Moon, Shield.  
Origin: Acanthus × Nomad.  
Inner Symbol is not included.

## 7. Product Grid

- 제품 수가 적으면 큰 image scale을 우선
- 4-column card wall을 자동 기본값으로 두지 않음
- price/status는 스캔 가능해야 함
- editorial interruption은 collection 이해에 기여할 때만

## 8. Product Detail

Desktop working structure:

```text
Gallery 7–8 columns
Summary 4–5 columns
```

Mobile:

```text
Gallery
→ name / price / state
→ size / action
→ delivery
→ story / meaning
→ specifications
→ care / policy
```

구매 action과 필수 배송정보가 긴 story 뒤로 숨지 않게 한다.

## 9. Brand / Founder Story

- founder history는 판단과 제작 통합 능력의 근거로 사용
- logo history나 timeline을 과도하게 만들지 않음
- product와 process image를 포함
- 브랜드와 founder를 하나의 biography page로 섞지 않음

## 10. Support Article

- title
- short summary
- anchor navigation when long
- clear sections
- tables only when comparison is needed
- contact escalation

## Pattern Selection Rule

한 page에서 3–5개 pattern을 조합하되 같은 pattern의 반복을 숨기기 위해 random variation을 만들지 않습니다. 각 변화에는 content hierarchy의 이유가 있어야 합니다.
